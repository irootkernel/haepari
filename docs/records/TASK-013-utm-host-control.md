# TASK-013 UTM host-control boundary

This record describes the candidate host adapter, not real backend qualification. Acceptance belongs to the [roadmap](../roadmap.md) and [EPIC-004 dossier](../roadmap/EPIC-004.md#task-013). TASK-034's historical probe informs the command boundary; TASK-016 must observe the current installed combination.

## Implemented surface

- Public VM registration checks UUID membership through `utmctl list` and resolves a digest-bound dedicated SSH host-key pin. Durable UUID/MAC uniqueness rejects duplicate registrations. Registration never boots or edits a VM.
- Idle VM updates require the current configuration and availability revisions, verify the successor UUID/pin and preserve availability/idle history. Occupancy and pending/uncertain power intents block updates. SQLite uniqueness errors are conflicts; other storage failures retain uncertainty.
- The host command adapter uses an absolute executable and literal argv with bounded time/output. It exposes only list, status, start and default forced stop. Nonzero exits, transport errors and exit-zero `Error from event` fail. Unknown/transient states are unavailable. It uses neither IP queries, display-name selection, AppleScript nor the UTM data container.
- The complete registered observation inventory feeds the existing durable host-place guard. Unregistered non-stopped UUIDs are conservatively counted, because list output cannot establish their OS; they are never automatic-stop candidates. Registered maintenance, policy, occupancy, transition and uncertain-power exclusions remain ledger decisions. Host-limit configuration and dispatch integration belong to TASK-015; the default remains one.
- The controller's power adapter claims the exact durable effect before issuing one command and records its successful return before power observations may advance that intent. The transition records its host claim origin independently of the replaceable progress proof; both persist across reopen, and the next effect resets the proof. Missing, malformed or inconsistent progress evidence cannot disable a host claim's return requirement. A delayed command, failed command or lost return remains protected even if another caller observes the desired status. A successful return still requires fresh fenced power observations; it is neither effect nor no-effect evidence. No issued effect is repeated. Stage vocabulary and ready-effect selection remain ledger-owned, with no new stage or schema migration.
- DHCP parsing requires one matching MAC entry with a parseable individual expiry later than now. Expired duplicates remain ambiguous. Pre-start and renewed entries require a currently started VM and pinned host/MAC/address/boot/nonce/OS/architecture proof; expiry and started state are rechecked. TASK-014 supplies authenticated transport to this verifier boundary.
- The existing machine no-effect observation and classification transactions retain the exact Job/resource/configuration/slot/lease fence, power reconciliation guard, VM-local `vm_unavailable` pause and atomic settling entry. Existing pause/quarantine survives; stale registration observations cannot apply. Settlement returns capacity once. TASK-015 connects these transactions to the guest preparation path before any guest effect.

## Verification and limits

The common test gate includes UTM unit checks and fake-boundary Unix controller integration. The [testing contract](../../TESTING.md#task-013-utm-host-adapter) names the new tests; existing scheduling, VM no-effect and power crash/reopen tests remain part of integration. Runtime run IDs, candidate digests and logs remain ignored local evidence, not tracked documentation.

VM Job admission remains unsupported, preventing the local runner from executing a VM workload. Public VM resume, removal and recovery are not implemented at this checkpoint. No host service or VM is installed, started, stopped or modified by these checks. Real SSH supervision, guest collection/cleanup, second-Job persistence and F2 are TASK-014 through TASK-016 outcomes; HP-REQ-025's integrated acceptance remains unclaimed. Local F1 wire shapes, runner receipts and SQLite schema 9 are unchanged. Release-note enrollment is absent (`not-enrolled`).
