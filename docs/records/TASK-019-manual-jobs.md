# TASK-019 general manual Jobs

The existing Job/manual-result contracts now connect to local and development
VM execution. Optional setup and workload smoke share one supervised native
preparation run and the original prepare deadline. The scenario document is
selected and sealed with the admitted input. Preparation success moves to
`awaiting_manual`, retaining the same capacity claim; it never creates a human
PASS or interprets consumer scenario content.

Private SQLite schema 10 journals exact preparation identity, installation,
original deadlines, stopped preparation facts, canonical human record and its
original completion receipt. First completion checks Job, profile, installation,
revision, required scenarios, cancellation and deadline transactionally.
`manual complete <job-id> --input <json> --expected-revision <n> --json` records
consumer assertions. Pass/fail need evidence references; unobserved required
checks prevent PASS. Exact canonical retry is checked before current state,
revision or deadline, and remains replayable after settlement/restart. Changed
completion records conflict. Bulk retention does not discard this replay owner.

Human workload facts are separate from native preparation exit/signal receipts.
Collection and cleanup use the existing physical evidence/ownership guards.
A human omission adds an explicit observation gap without authorizing deletion
of unknown physical evidence. Preparation failure, deadline and cancellation
never manufacture observations; missing outputs/evidence remain INCOMPLETE under
the existing verdict table, even when the workload fact is cancelled. Caller
exit and wait expiry leave the Job alive. Explicit cancellation or the original
deadline retires completion authority before bounded owned settlement. A restart
between the deadline-intent and abort commits reuses the original retired intent
across the new revision; it cannot conflict on a replayed mutation key.

Restart observes the original run and filesystem incarnation, resumes preparation
or the original awaiting deadline, and never repeats setup. Completed decisions
resume collection/cleanup. Unproven owners, replaced roots and legacy holds
without native preparation facts remain reconciling/occupied until supported
recovery supplies the missing proof. No arbitrary human process is adopted as
Haepari-owned work.

[TESTING.md](../../TESTING.md) identifies enrolled real local CLI and scripted
SSH/native guest fixtures. These use synthetic human records, including
pass/fail/unobserved, exclusive capacity, exact/conflicting retry, invalid
identity/scenario records, caller expiry, original deadline, cancellation,
controller crash and successor reuse. The schema-9 SQL fixture is generated by
an actual baseline binary; supplementary synthetic downgraded layouts remain
separate. Schema-10 missing-storage checks refuse to recreate lost session data.
The workspace journal admits a preparation RunID only for its exact non-legacy
manual claim, and stores the original RunID-less workspace identity. Manual
prepare compensation extends the existing state gates only under that same
private session fence. Registration derives mode from immutable admission.
Late completion is tested before abandonment commits and after settlement;
neither records a human PASS or renews the original deadline. Native guest
recovery preserves the original preparation and awaiting deadlines and refuses
unknown, live-worker or partial-preparation observations without another setup.
Coupled physical and human evidence checks preserve known positive absence,
protected uncollected bytes, quarantine and occupied unproven reconciliation as
distinct existing outcomes. Safe field diagnostics identify an unsealed scenario
or unsupported result schema without exposing supplied values; the helper also
refuses non-selected scenario documents before admission.
The private runner constructor owns its dispatch strings; shared manual
collection policy separates observation gaps from physical evidence. Native
workflow evidence and exact candidate bindings remain local; acceptance
belongs to [the roadmap](../roadmap.md).

No actual human product pass, live VM manual release observation, provider test
workload, installation or service activation is claimed. TASK-020 combines and
freezes F3; TASK-027 owns the packaged candidate's running-VM manual observation.

## Recovery follow-up

In-flight VM preparation recovery now consumes the authenticated guest's
supervisor liveness instead of interpreting its process identity on the host.
False or missing guest proof still blocks recovery; local preparation retains
its native host identity check. Explicit manual recovery preserves the public
request key and client digest through the same durable recovery transaction,
so its original receipt remains replayable after completion and controller-key
rotation. Automatic startup retains its internally derived recovery identity.

The corresponding integration fixtures cover local and fake/native VM public
recovery, exact and conflicting replay, one preparation/run, original deadlines
and verified cleanup. The live-preparation fixture supplies a scripted guest
supervisor identity absent on the host and checks unchanged recovery state for
false or unknown liveness. These are isolated regression checks, not a real VM
or human product observation. Existing phase timing semantics remain unchanged.
