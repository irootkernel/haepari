# TASK-016 VM contract freeze decision

Decision date: 2026-10-05. Effective when TASK-016 becomes Accepted in the [canonical roadmap](../roadmap.md). This record defines the candidate F2 boundary; it does not independently accept the Task or Epic. The accepted Task commit and its review/verification evidence identify the exact frozen bytes.

## Scope and authorities

F2 freezes the implemented `utm-macos` resource fields, authenticated guest request/reply and worker protocols, VM interpretation of native run identity, host-session ownership, and VM-specific Job/result behavior. Semantic owners remain [resource/runner](../contracts/resource-and-runner.md), [CLI/jobs](../contracts/cli-and-jobs.md), [managed transitions](../contracts/managed-transitions.md), and [configuration](../contracts/configuration.md). The accepted code's typed contracts and validators are the complete field inventory; the table below identifies those owners rather than introducing a second schema.

The [F1 decision](TASK-012-managed-core-freeze.md) continues to own common admission, local execution, native runner receipts, outcomes, artifact delivery and evidence-recovery schemas. F2 specializes those existing bindings for a separate guest filesystem; it changes neither F1 local execution nor storage schema 9. Manual completion, environment locks, consumer installation conventions and the general configuration loader remain with their later tasks. Public external leases remain unsupported.

## Qualified combination and evidence boundary

The current qualification covers UTM 4.7.5 on an Apple Silicon macOS 27.0.1 (26A434) host, an arm64 macOS 27.0.1 (26A434) persistent guest using the Apple Virtualization backend, and the installed development Aqua LaunchAgent. The real campaign uses one designated already-running registered VM, strictly pinned SSH and harmless offline guest recipes. Registration, preparation and observed VM availability do not imply that a cold VM start was performed in this campaign.

Observed installed-candidate paths include successful execution and a second Job, deliberate workload failure, explicit cancellation, actual SSH observer interruption, controller restart with original-run recovery, complete collection/cleanup and next-Job readiness. A fresh missing required output retains the exact guest Job, blocks its successor, then undergoes explicitly authorized disposal and separate native health before a successful reuse Job. Original terminal results and collected host artifacts remain immutable. Native host screen-lock observations cover preparation through collection and cleanup; screen lock is not logout.

## Owner-approved later verification

The owner waived actual expired DHCP-entry rejection and host logout/post-login recovery for the current TASK-016 campaign. [DF-001 and DF-002](../deferred-feedback.md) own their remaining uncertainty, authority and re-entry conditions; both must be verified before TASK-027 release acceptance. They are unobserved, not passed, and the waiver is not permanent removal. Current Task completion may rely on the explicitly accepted deferrals while retaining these limits.

F2 freezes the stated contract, not every unobserved environmental behavior. TASK-017 may consume the frozen VM field semantics after canonical TASK-016 acceptance; TASK-027 must close the deferred real checks and requalify its exact release candidate before release acceptance. Power-loss durability, additional platforms, production release services and external providers remain with their own tasks and authority.
